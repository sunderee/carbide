# Adopting Carbide 0.5.0

This guide describes the completed M13–M18 work relative to the published
`v0.4.2` tag. It documents the prepared 0.5.0 API; publication and the version
bump are separate release actions. Use the checked [parity](../carbon-parity.md),
[platform](../platform-support.md) and [stability](../api-stability.md) policies
when deciding what the port guarantees.

## Changes to existing applications

| Area | Migration or visible behavior |
| --- | --- |
| SDK | Upgrade both application and package tooling to the current minimum Flutter 3.47.6 / Dart 3.13.5. The 0.4.2 floors were Flutter 3.44.0 / Dart 3.12.0. CI checks both declared minimum and latest stable. |
| Bundled fonts | Fixed/fluid, AI and pagination-nav styles now resolve the package's actual Plex families in consumers. Text widths can change from platform fallback fonts; recheck constrained layouts. Plain CarbonFontFamily names remain stable. |
| Public API | TagSurface is hidden from the barrel. Replace direct use with CarbonTag, CarbonDismissibleTag, CarbonSelectableTag or CarbonOperationalTag. Direct src imports are unsupported; the unexported scroll helper was also renamed internally. |
| Tabs | CarbonTabs and CarbonTabsVertical constructors are no longer const. Remove const from those constructor calls; CarbonTab value objects can still be const. Supply matching tab/panel lengths and valid controlled indexes. |
| Numeric entry | Number-input typing is a draft; Enter, Done, blur and step actions commit a finite clamped value and normalized display. Use a finite positive step. Do not depend on a callback for every incomplete keystroke. |
| Text-area limits | maxCount applies to committed input and paste with grapheme/word counting. IME composition is preserved until commit. Do not duplicate the limit with a code-unit substring operation. |
| Controlled selectors | A missing onChanged disables callback-driven Select, Dropdown and MultiSelect. Use readOnly for reviewable values that should remain focusable. Search/query editing retains its documented uncontrolled behavior. |
| Pagination | Positive sizes/pages and nonnegative totals are validated. Invalid page-size lists fail at build; stale pages clamp to the current result set, and zero results use page one with disabled arrows. |
| Compact/scaled layout | Field, menu, legend and toolbar chrome can grow with text. Pagination selectors use the full target band. Content-switcher labels retain a minimum readable width and scroll rather than shrinking every segment to fit. |
| Progress steps | Horizontal steps use the 128px grid and can scroll; vertical steps wrap and grow beyond their 58px minimum. Recheck containers that assumed compressed steps or fixed text height. |
| Overlays | Viewport flips/clamping, controlled date-range drafts, exit lifetimes and native focus repairs are now part of the contracts. A newer focused control takes precedence over an old overlay's repair. |

The complete [changelog](../../CHANGELOG.md) includes the behavior fixes and
additions. The immutable value/style APIs and deliberate advanced composition
surface follow the [compatibility policy](../api-stability.md); advanced does
not authorize silent patch-release breaks.

## Fonts, themes and text

Built-in Carbon styles require no extra font loader in an application. They
qualify only the Plex family, so an inherited application Japanese/Arabic
fallback or a copyWith family override keeps its own name. For a custom style
using a plain descriptor, provide its package explicitly:

```dart
const TextStyle(
  fontFamily: CarbonFontFamily.mono,
  package: CarbonFontFamily.package,
)
```

Flutter's package argument also qualifies that style's fallback families.
Use already-qualified primary names when mixing application fallback fonts, as
explained in [consumer font resolution](../testing/font-resolution.md).
Carbide bundles seven Sans/Mono/Serif files, not the whole Plex catalog.
Applications supply fonts for additional scripts and platform-specific needs.

CarbonTheme resolves the nearest high-contrast preference; CarbonLayer shifts
contextual tokens. Use CarbonText for ordinary themed labels, or an explicit
Carbon style/color on Text. CarbonTheme alone does not replace the application's
DefaultTextStyle. Keep the requested text scaler: the library grows supported
chrome instead of capping accessibility text size.

## Responsive PageHeader adoption

Existing custom pageActions remain available. Opt into measured actions with
`actions`; the two APIs are mutually exclusive. Put the primary action first
and use stable unique IDs. Null callbacks disable actions in both their button
and overflow representation. collapseTags is opt-in; without it tags wrap.
Provide localized disclosure labels where needed.

The title always exposes its full heading name. Only a truncated title adds a
pointer/keyboard tooltip; fitting titles add no focus stop. The hero is an
optional caller-owned widget that reflows with the text column. Stateful hero
and tag children should have stable keys; keep their controllers and resources
with their owner. Images must have an appropriate label or decorative policy.
The gallery's sample image has its own NOTICE attribution; consumers using
that copied asset must declare it in their application assets.

```dart
import 'package:carbide/carbide.dart';
import 'package:flutter/widgets.dart';

class ResponsiveHeaderExample extends StatefulWidget {
  const ResponsiveHeaderExample({super.key});

  @override
  State<ResponsiveHeaderExample> createState() => _ResponsiveHeaderExampleState();
}

class _ResponsiveHeaderExampleState extends State<ResponsiveHeaderExample> {
  int _edits = 0;

  @override
  Widget build(BuildContext context) => Column(
    mainAxisSize: MainAxisSize.min,
    crossAxisAlignment: CrossAxisAlignment.start,
    children: <Widget>[
      CarbonPageHeader(
        title: 'Quarterly report for the regional operations team',
        subtitle: 'Finance',
        body: 'A summary of revenue and spend.',
        actions: <CarbonPageHeaderAction>[
          CarbonPageHeaderAction(
            id: 'edit',
            label: 'Edit report',
            onPressed: () => setState(() => _edits++),
          ),
          const CarbonPageHeaderAction(id: 'archive', label: 'Archive report'),
        ],
        collapseTags: true,
        tags: const <Widget>[
          CarbonTag(key: ValueKey<String>('finance'), label: 'Finance'),
          CarbonTag(key: ValueKey<String>('emea'), label: 'EMEA'),
          CarbonTag(key: ValueKey<String>('review'), label: 'Needs review'),
        ],
        hero: const CarbonTile(child: CarbonText('Report overview')),
      ),
      CarbonText('Edits: $_edits'),
    ],
  );
}
```

Carbide retains the historical header band and constructor composition.
The newer compound core PageHeader scrolling/collapse orchestration is deferred
with its upstream v12 export. See the [header recipe](../patterns/page-header.md)
for measured widths, hero ratios, ownership and keyboard behavior.

## Scaling, density and overflow

ContentSwitcher retains equal segment widths within a shared horizontal scroll
view when the minimum readable label space exceeds its host. Arrow keys,
Home/End and controlled selection reveal the relevant segment. Icon-only items
keep intrinsic square geometry. The low-contrast variant remains tracked in
[#384](https://github.com/sunderee/carbide/issues/384); it is not shipped by this pass.

Horizontal ProgressIndicator labels remain one line with full accessible names;
vertical labels wrap. The Flutter horizontal band reserves supporting-text
height, unlike the historical CSS positioning outside its list box. This is an
intentional documented framing difference, not pixel parity. Choose vertical
steps for touch-heavy or very narrow flows.

Provide enough width for table columns/batch actions, or use a horizontal scroll
host with an explicit content width. Avoid intrinsic measurement around virtual
viewports. Compact Carbon controls can be below mobile target-size guidance;
choose appropriate density and check the actual host, as described in the
[platform matrix](../platform-support.md).

## Picker data, identity and ownership

Existing eager items retain their normal rendering mode. itemBuilder/itemCount
opt into bounded mounting and operate on option metadata, not Widget builders.
Supply both, omit eager items, and keep values stable. Builders must be pure
and cheap; filtering, selected-value lookup and typeahead may still scan the
source metadata. Bounded mounting is not a constant-time data guarantee.

```dart
import 'package:carbide/carbide.dart';
import 'package:flutter/widgets.dart';

class LazyAccountExample extends StatefulWidget {
  const LazyAccountExample({super.key});

  @override
  State<LazyAccountExample> createState() => _LazyAccountExampleState();
}

class _LazyAccountExampleState extends State<LazyAccountExample> {
  int _selected = 1;

  @override
  Widget build(BuildContext context) => SizedBox(
    width: 360,
    child: CarbonDropdown<int>(
      titleText: 'Account',
      selectedItem: _selected,
      itemCount: 10000,
      itemBuilder: (int index) => CarbonDropdownItem<int>(
        value: index,
        label: 'Account ${index + 1}',
        disabled: index % 97 == 0,
      ),
      onChanged: (int value) => setState(() => _selected = value),
    ),
  );
}
```

Use readOnly to preserve review/selection/copy access while preventing changes;
disabled skips traversal. Opening a picker does not make its highlighted option
the committed value. Enter/Space or an option action commits according to the
control contract, and multi-select toggles controlled values. Editable pickers
retain their query, selection and IME range while navigating. See
[lazy options](../lazy-options.md) and [forms](../patterns/forms.md).

Borrowed controllers, focus nodes and scroll controllers belong to the caller.
Dispose them when their owner leaves, not when a field restyles or an overlay
closes. The library disposes only resources it creates. Preserve stable keys
for stateful/reordered children and stable record/option IDs for reconciliation.

## Large tables and trees

Eager rendering remains the default and supports intrinsic layouts. The
recorded guidance envelope is up to 100 ordinary rendered records; it is not a
portable time/memory promise for complex cells or every device. Paginate or opt
into virtualized views for larger data and profile the real application.

```dart
import 'package:carbide/carbide.dart';
import 'package:flutter/widgets.dart';

class RecordTableExample extends StatefulWidget {
  const RecordTableExample({super.key});

  @override
  State<RecordTableExample> createState() => _RecordTableExampleState();
}

class _RecordTableExampleState extends State<RecordTableExample> {
  final ScrollController _scroll = ScrollController();
  Set<Object> _selected = <Object>{};
  Set<Object> _expanded = <Object>{};

  @override
  void dispose() {
    _scroll.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => CarbonDataTable(
    columns: const <CarbonTableColumn>[CarbonTableColumn(title: 'Name')],
    rows: <CarbonTableRow>[
      for (int index = 0; index < 1000; index++)
        CarbonTableRow(
          id: 'record-$index',
          label: 'Record $index',
          cells: <Widget>[CarbonText('Record $index')],
          expandedContent: CarbonText('Details for record $index'),
        ),
    ],
    virtualized: true,
    viewportHeight: 320,
    stickyHeader: true,
    scrollController: _scroll,
    selection: CarbonTableSelection.multi,
    selectedRowIds: _selected,
    onSelectedRowIdsChanged: (Set<Object> ids) => setState(() => _selected = ids),
    expandable: true,
    expandedRowIds: _expanded,
    onExpansionChanged: (Set<Object> ids) => setState(() => _expanded = ids),
  );
}
```

IDs must be unique and non-null for virtual tables. Prefer selectedRowIds and
expandedRowIds over the deprecated index-based APIs; indexes change after a
sort/filter. Focused rows stay mounted while they own focus; durable drafts in
other recycled rows belong in models or owned controllers. Data indexes remain
proportional to the source size. Long jumps through variable-height table rows
can refine the estimated extent as rows are measured. See
[large-data contracts and measured limits](../large-data.md).

TreeView has separate controlled active, selected and expanded state, plus
multiselect. Keyboard reveal can reach nodes whose widgets have never mounted.
Do not derive persistent IDs from a current visual index.

## Dates, time and validation

DatePicker selects civil dates through a calendar. A range draft commits once
both dates are chosen; dismissal, trigger toggles or becoming read-only discard
an incomplete session. External controlled changes rebase the session. Calendar
bounds, month/day navigation and localized formats are validated. CarbonDateFormat's
parser can support a separate application text-entry workflow; the picker is
not a free-form date editor.

TimePicker remains permissive when format is omitted. Supplying CarbonTimeFormat
opts into draft parsing, normalization and Enter/Done/group-blur commits;
invalid drafts remain visible and do not invoke success callbacks. Moving into
AM/PM or a coordinated select does not commit the draft. Provide localized
invalidText and use onCommitted for canonical civil time. See
[date localization](../patterns/date-pickers.md),
[time policies](../patterns/time-pickers.md) and
[pagination validation/localization](../pagination.md).

## Overlays, gallery and release verification

Keep Overlay/WidgetsApp, Directionality, MediaQuery and CarbonTheme available
around examples. Menus/popovers use measured viewport placement and preserve
focus through native semantics updates. Modal/dialog exit motion retains their
focus boundary until removal; reopening cancels removal and reduced motion
removes immediately. Applications still own open state and resource lifetime.

CodeSnippet and Copy affordances are keyboard/AT activatable; the gallery's
expanded/copied text is a full functional example reflecting current controls.
FileUploader is presentation: the application owns file selection, platform
drop integration, validation and transport. Its gallery adapter is explicitly
in memory. See [upload integration](../patterns/file-upload.md).

The release graph verifies root and independent gallery packages, source/fidelity
freshness, Linux goldens, accessibility/lifetime inventories, native Chromium
focus/fonts/routes, declared minimum SDK, generated docs and strict archive
validation. Host/browser evidence does not replace native mobile/desktop app
validation or imply Safari/Firefox coverage. Reviewed gaps remain explicit in
the parity matrix; Carbon Charts stays in M19 (#357), beyond this release.
