## Behavior and regression coverage

- **#292:** Row selectors and select-all expose one merged accessible node,
  preserving labels, checkbox/radio states, mixed selection, disabled state,
  focus actions, and tap actions. Tests exercise semantics activation and
  semantics focus followed by keyboard activation, exact callback counts,
  selection-mode changes, and all accessibility guidelines.
- **#293:** Interactive progress steps support semantics activation, Enter,
  and Space through the shared interaction primitive. Both orientations cover
  every step state, disabled and callback-free configurations, one actionable
  node per step, accessibility guidelines, and keyboard-only focus rings.
- **#294:** Both tabs constructors reject empty tabs, unequal tab/panel counts,
  and invalid controlled indices in debug builds. Selection clamps safely in
  release builds and reconciles shrinking lists and transitions between
  controlled and internal selection without callbacks during build. Tests
  cover these contracts in both orientations. A real Chrome integration test
  also passed in `--release`, explicitly checking that assertions were disabled.

The tabs constructors are now non-const because Dart cannot evaluate these
list-length assertions in a const constructor. Callers must remove `const`
from `CarbonTabs` and `CarbonTabsVertical` construction. The library docs and
changelog describe this change.

## Browser and visual review

Used the running web gallery in Chromium 149 at 1440 × 1100. Exercised DOM
semantics activation, ordinary pointer clicks, browser focus, Enter, Space,
arrow navigation, configuration controls, and theme switching. Inspected actual
browser screenshots and the Linux-generated golden images.

Table checks included multi-select, select-all/clear, partial selection,
full-cell pointer targets, radio exclusivity, keyboard activation, disabled
selectors, and changing selection mode. Progress checks included both
orientations, assistive-technology tap actions, Enter/Space activation,
disabled/noninteractive steps, and visible keyboard focus. Tabs checks included
pointer and arrow-key navigation with the corresponding panels in both
orientations. Reviewed all three components across all four themes. No browser
runtime errors occurred. This validates the browser accessibility surface;
an interactive VoiceOver/NVDA session was not performed.

Browser review found and fixed additional defects: excluded focus semantics
prevented DOM focus from reaching Flutter; changing table selection mode
retained an old checkbox role; and an inactive animated batch bar could paint
outside its header and expose its Cancel action. Regression tests cover these
paths.

Flutter 3.47's web semantics engine currently serializes mixed checkboxes as
`aria-checked="false"`. The table retains the correct native mixed flag and
adds “Partially selected” to the same node's value on web so the state remains
announced. Disabled progress steps expose their “Disabled” value as inert text.

Validation scripts, browser captures, logs, and downloaded browser tooling are
local ignored artifacts under `.agent/validation/`. No Cursor, Claude Code,
Codex, or other agent rule files were added to version control.
